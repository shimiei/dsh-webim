## 手机上不再和宿主抢布局

更新到 DSH 0.2 之后，手机端抽屉能打开了，但里面空空如也：工作区只剩几根空药丸，标题全被推到屏幕左边外面，左上角还压着 webim 自己的 ☰。看着像「官方原生」坏了，其实是 webim 那套旧的手机布局在跟宿主打架。

### 原因

0.2 起手机布局归宿主：frame 上是 `data-sidebar-drawer` + `data-sidebar-collapsed`，narrow 屏它会自己把 rail 变成抽屉。webim 还在按老办法改列宽（`grid-template-columns: 1fr`）、给 rail 加固定宽度和 `width:100%` 覆盖，于是抽屉外壳挪到位了，里面的内容仍按旧轨道排版——整体偏到可视区外。

### 改法

- 只要宿主有 `data-sidebar-drawer`，webim **整套手机布局都不参与**：不加 `webim-mobile`、不加任何覆盖样式、也不压自己的 ☰（用宿主自带的开关）；
- 启动时宿主可能还没渲染，先按旧版跑，之后每 500ms 探一次，一旦发现宿主抽屉立刻把自己那一层拆干净；
- 没有这个属性的旧版，行为与以前完全一致。

### 顺带修掉：入口 pill 永久隐身

0.2 把侧边栏外壳也标成 `role="dialog"`（同时 `visibility:hidden`），而我们「对话框挡住时藏起 pill」的规则只认 `body:has([role="dialog"])`，于是 pill 永远 `opacity: 0`——手机上根本点不到入口。现在改由 JS 判断「真的有对话框占屏」时才隐藏。

### 实测

| 场景 | 结果 |
| --- | --- |
| 390px 打开抽屉 | x=0、w=280，内容与原生一致（工作区名称齐全） |
| 390px 首页 pill | 可见，opacity 1 |
| 1280px 桌面 pill | 正常显示在右下角 |
| 布局覆盖类 | 390 / 1280 下都没有给宿主加任何类 |

`node --test tests/*.test.mjs` → **115 pass**。
